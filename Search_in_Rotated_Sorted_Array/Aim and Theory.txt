Search in Rotated Sorted Array

Aim
To understand how to efficiently search for an element in a rotated sorted array using Binary Search by identifying the sorted half of the array at each step.

Definition
Search in Rotated Sorted Array is a searching algorithm that locates a target element in a sorted array that has been rotated at an unknown pivot. Instead of performing a linear search, the algorithm modifies Binary Search to achieve logarithmic time complexity.

Theory
A rotated sorted array is formed by taking a sorted array and rotating it around a pivot point. For example:

Original:
[1, 2, 3, 4, 5, 6, 7]

Rotated:
[4, 5, 6, 7, 1, 2, 3]

Although the array is no longer completely sorted, at least one half of the array remains sorted during every Binary Search iteration. By identifying the sorted half and determining whether the target lies inside that range, the search space can be reduced by half in every step.

This property allows the algorithm to maintain the same logarithmic efficiency as Binary Search.

Working Principle

1. Initialize two pointers:
   - left = 0
   - right = n - 1

2. Compute the middle index.

3. If the middle element equals the target, return its index.

4. Determine whether the left half is sorted.
   - If nums[left] <= nums[mid], the left half is sorted.

5. Check whether the target lies inside the sorted half.
   - If yes, discard the other half.
   - Otherwise search the remaining half.

6. If the left half is not sorted, then the right half must be sorted.

7. Again determine whether the target belongs to the sorted right half.

8. Continue until the element is found or the search space becomes empty.

Advantages

• Runs in O(log n) time.
• More efficient than linear search.
• Uses Binary Search principles.
• Requires only constant extra memory.
• Suitable for large rotated arrays.

Disadvantages

• Assumes all elements are distinct in the standard version.
• Slightly more complex than standard Binary Search.
• Additional comparisons are required to determine the sorted half.
• Handling duplicate values requires modifications.

Time Complexity

Best Case:
O(1)

Average Case:
O(log n)

Worst Case:
O(log n)

Space Complexity

O(1)
